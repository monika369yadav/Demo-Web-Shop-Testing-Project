📌 Project Overview

A complete manual testing portfolio project performed on the Demo Web Shop (sample e-commerce application by Tricentis), built to demonstrate practical QA skills including test case design, exploratory testing, bug reporting, and requirement traceability. This project simulates a real-world QA engagement — independently planning, designing, and executing manual test cases, identifying defects, and maintaining full testing artifacts the same way a QA Tester would in an actual product team.

🌐 Application Under Test

Application:Demo Web Shop
URL:demowebshop.tricentis.com
Type:Sample E-Commerce Web Application (built on nopCommerce)
Provided by:Tricentis (for public QA practice and training)

🎯 Testing Scope

  • Functional testing of core e-commerce flows (Browse, Cart, Checkout, Account)
  • UI/UX validation and usability observations
  • Cross-browser sanity checks
  • Negative and boundary testing on forms and inputs
  • Defect identification, classification, and reporting

Out of Scope: Performance testing, security/penetration testing, backend/database testing, automated test execution

🧩 Modules Tested

Books Computers Electronics Shopping Cart Checkout Register / Login Search

🛠️ Tools Used

  • Browser DevTools — UI inspection, responsive checks
  • Markdown / GitHub — Test documentation and version control
  • Snipping Tool — Visual defect evidence
  • ChatGPT / Claude AI — Assisted in structuring documentation and brainstorming test scenarios

🔍 Key Findings & Observations

  • Site-wide pattern: Products missing "Add to Cart" button and stock-status message — found across Books, Computers (Desktops), and Electronics (Camera/Photo, Cell phones), not limited to one category
  • Critical: Store search returns "No products found" for every keyword tested, including exact, existing category names like "Books" and "Computers" — search is effectively non-functional
  • Manufacturer page ("Tricentis") renders with no products and no empty-state message
  • State/Province dropdown does not list actual states when Country = India during checkout
  • Register, Login (positive and negative paths), and Gift Card recipient validation all function correctly
  • Cart and pricing calculations, including payment-method additional fees, were verified to be accurate at checkout

🐛 BUG-001 Open

Title:Missing "Add to Cart" button and no stock-status message across multiple product categories
Module:Books Computers Electronics
Description:Several products across multiple categories do not display an "Add to Cart" button, with no alternative "Out of Stock" message. First found in Books, then confirmed in Computers (Desktops) and Electronics (Camera/Photo, Cell phones) — indicating a site-wide pattern, not a one-off issue.
Steps to Reproduce:1. Navigate to Books, Computers → Desktops, or Electronics → Camera/Photo / Cell phones  2. Observe the product grid  3. Note some products show price/rating but no "Add to Cart" button
Test Data:Fiction, Fiction EX (Books); Desktop PC with CDRW, Elite Desktop PC, Simple Computer (Desktops); all 4 products in Camera/Photo; Used phone (Cell phones)
Expected Result:Every product should either show an "Add to Cart" button (if purchasable) or a clear status message explaining why it cannot be purchased
Actual Result:Affected products display price and rating, but no purchase option and no explanation is shown, across multiple categories
Severity:High (escalated from Medium — repeats across 3+ categories)
Priority:High
Environment:Chrome, Desktop, demowebshop.tricentis.com
QA Note:Does not break functionality (page loads fine, no error) but creates user confusion about availability — also cross-logged as UX suggestion SUGG-001.

Environment:Chrome, Desktop, demowebshop.tricentis.com

💡 SUGG-001

Related Bug:BUG-001
Module:Books
Observation:Some products on the Books listing page do not show an "Add to Cart" button, and there is no message indicating stock status (e.g., "Out of Stock," "Currently Unavailable," "Coming Soon").
Impact on User:Users may assume the product is broken, the page failed to load correctly, or feel confused about why they cannot purchase the item — leading to a poor browsing experience and potential loss of trust in the platform.
Recommendation:Display a clear status label (e.g., a greyed-out "Out of Stock" button or a small badge like "Unavailable") in place of the missing "Add to Cart" button, so users always understand product availability at a glance.
Priority:Medium
Category:Usability / Communication Gap

💡 SUGG-002

Related Bug:N/A
Module:Shopping Cart
Observation:The cart page does not have a dedicated "Remove" button per item. Users must check a small checkbox in the "Remove" column, then click a separate "Update shopping cart" button — a 2-step process.
Impact on User:Users familiar with a single-click "Remove" (common on most e-commerce sites) may not realize they need to check the box AND click Update — leading to confusion or accidental cart changes.
Recommendation:Add a direct "Remove" icon/button next to each cart item that removes it immediately on click, without needing a separate checkbox + update step.
Priority:Low
Category:Usability
